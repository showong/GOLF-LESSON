# 골프 레슨 튜더 (Golf Lesson Tutor)

스크린골프장에서 얻은 스윙 영상을 업로드하면, **Gemini 3.1 비전 모델**이 영상을
분석해 **클럽 종류(드라이버/아이언/어프로치)** 를 자동으로 인식하고,
**등급(골린이·아마추어·세미프로·프로) × 단계(LV-1~3)** 로 평가한 뒤
**등급 전담 코치 페르소나**가 사용자 친화적인 톤으로 칭찬·지적·드릴을
한 번에 제공하는 Next.js 웹앱입니다.

## 주요 기능

- 📱 **모바일 친화 UI / PWA**: 스마트폰에서 카메라로 즉석 촬영 → 바로 업로드.
  추천 영상·기록 카드는 가로 스와이프, "홈 화면에 추가"로 앱처럼 사용 가능.
- 🎥 **멀티 시점 영상 분석**: 측면샷(권장) + 정면샷(선택) 1~2개의 영상을 함께 업로드 가능.
  시점별 강점(측면=플레인/자세각, 정면=정렬/스웨이)을 활용해 더 정확한 분석.
- 📺 **YouTube 추천 영상**: 헤드코치가 짚은 핵심 약점·포커스를 한국어 검색어로 변환해
  YouTube Data API로 추천. 화이트리스트 채널(SBS골프·JTBC골프·골프존 등)이 상단 우선 표시.
- 🎯 **클럽 자동 인식**: 어드레스/볼 위치/스윙 길이/티 사용 여부를 종합해
  드라이버·아이언·어프로치 중 하나로 판정.
- 🏆 **등급 + 단계 판정**: 헤드코치 박상민이 골린이→아마추어→세미프로→프로
  4단계 × LV-1~LV-3을 부여.
- 🧑‍🏫 **등급별 전담 코치**: 골린이는 다정한 김다정 코치, 프로는 절제된 한지호 코치 등
  등급에 맞는 어휘와 톤으로 코멘트.
- 🧠 **메모리(이전 기록) 반영**: 서명된 사용자 ID의 직전 분석 요약을 컨텍스트로 넣어
  변화 추이(▲상승/▼하락/=유지)를 표시.
- 📋 **숙제 검사 루프**: 지난 분석의 #1 포커스를 코치가 기억하고, 다음 분석에서
  개선 여부(좋아짐/비슷함/후퇴)를 직접 판정해 알려줌.
- 📈 **성장 게이지**: 등급은 보수적으로 유지하되, 가중 점수(0~30)와
  "다음 단계까지 N점" 진행 표시 + 항목별 ▲▼ 변화로 세밀한 진척을 노출.
- 🔍 **관찰 기반 개별 진단**: 스윙 위상 자동 감지(2-pass 프레임 추출) +
  하체/상체/축 3인의 부위별 분석관이 관찰만 수행 → 코치는 관찰 근거를 인용해야만
  약점을 진단 가능(상투 진단 금지 + 바넘 테스트 리뷰). 흔한 결함은 서브타입까지
  감별해 사람마다 다른 드릴 처방.
- ⚠️ **잠정 등급**: 클럽 인식 신뢰도가 낮거나 관찰 한계가 많으면 등급에 "잠정"
  배지를 붙이고 구체적인 재촬영 가이드를 제공. 판독 범위가 부족하면 점수 감점 없이
  등급 상한만 제한(커버리지 캡)하고 성장 게이지를 숨겨 모순 표시를 방지.
- 🦴 **브라우저 스켈레톤 분석**: 업로드 전 사용자 기기에서 MediaPipe Pose로 관절
  좌표를 추출(서버 비용 0). 위상 감지를 결정적 수학으로 대체하고, 템포·스웨이·척추각
  등 정량 지표(어깨 폭 대비 상대 단위)를 코치 프롬프트에 주입. 미지원 기기는
  Gemini 위상 감지 → ffmpeg 모션 분석 → 고정 비율 순 폴백. 분석 직후에는 등급 카드
  아래에 어드레스·백스윙·탑·임팩트·피니시 스켈레톤 프레임과 구간별 부족한 점·개선
  체크를 표시하며, 원본 영상과 시각화 이미지는 서버에 저장하지 않음.
- 🎯 **드릴-서브타입 매칭**: 감별된 결함 서브타입(시퀀스형/얼리 익스텐션형 등)별
  집·회사 드릴 템플릿 라이브러리에서 처방. 각 드릴에 targetSubtype 명시, 리뷰에서 정합성 채점.
- 📝 **관찰 인용 강제**: 헤드코치 채점 노트는 부위별 분석관 관찰(evidenceSource) 인용 필수.
  인용 없는 채점은 신뢰도 자동 하향 → 잠정 판정 유도.
- 🔁 **멀티샷 분석**: 같은 클럽 스윙을 최대 3개까지 등록하고 각 스윙에 측면·정면
  영상을 함께 올릴 수 있습니다. 서버가 스윙별로 독립 채점한 뒤 중앙값과 일관성 점수를
  계산하고, 문제를 **공통 문제(60%↑) / 간헐적 / 빈도는 낮지만 크리티컬**로 분류합니다.
  업로드 화면에서 "정밀 분석"과 별도 탭으로 제공합니다.
- 🧪 **회귀 테스트**: `npm test` — 등급 매핑·게이트·커버리지 캡·포즈 위상 감지·
  세션 집계(중앙값/일관성/빈도 분류)의 결정적 로직을 검증하는 미니 하네스.
- 📊 **클럽별 진척 대시보드**: 드라이버/아이언/어프로치를 **각각의 섹션**으로
  나눠 등급·단계 추이를 시각화.

## 기술 스택

- **프레임워크**: Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS
- **AI**: Google Gemini 3.1 (`@google/genai`) — File API로 영상 업로드
  후 멀티모달 분석
- **영상 전처리**: ffmpeg (`ffmpeg-static`) — 실제 fps에 맞춰 어드레스/탑/임팩트/피니시
  키 프레임을 추출하고 임팩트 전후 ±3프레임 버스트를 함께 전달합니다.
- **촬영 품질 게이트**: 해상도·fps·길이와 전신 프레이밍·클럽/볼 노출·카메라
  안정성을 검사하고, 항목별 관찰 가능 여부와 신뢰도를 판정에 반영합니다.
- **데이터**: PostgreSQL — 사용자·영상·분석·작업을 사용자 ID 기준으로 영속 저장
- **작업 처리**: Redis + BullMQ Worker — 웹 요청과 장시간 영상 분석 분리
- **영상 저장**: Railway Storage Bucket — 브라우저가 presigned URL로 직접 업로드
- **UI 언어**: 한국어

## 시작하기

```bash
# 1. 의존성 설치
npm install

# 2. 환경 변수 설정
cp .env.example .env.local
# .env.local 을 열어 GEMINI_API_KEY 를 채워주세요.

# 3. 기존 서버와 함께 실행할 배포용 개발 서버
npm run dev:deploy
# http://localhost:3001
```

### 환경 변수

| 키 | 설명 |
|---|---|
| `GEMINI_API_KEY` | Google AI Studio에서 발급한 키 (필수) |
| `GEMINI_MODEL` | 기본 `gemini-3.1-flash-lite`. 멀티모달/비디오 지원 모델이어야 함 |
| `SESSION_SECRET` | 사용자 소유권 쿠키 서명 키. 운영 환경에서 32바이트 이상 필수 |
| `DATABASE_URL` | Railway PostgreSQL 연결 URL. 로컬에서 비우면 PGlite 사용 |
| `REDIS_URL` | Railway Redis 연결 URL. 운영 환경에서 Worker 분리에 필수 |
| `STORAGE_MODE` | 운영 환경은 `s3`, 로컬은 `local` |
| `BUCKET_*` 또는 `AWS_*` | Railway Bucket endpoint·bucket·access key·secret·region |
| `MAX_UPLOAD_FILE_BYTES` | 영상 1개 최대 크기. 기본 80 MiB |
| `MAX_UPLOAD_TOTAL_BYTES` | 요청 1회 총 업로드 크기. 기본 240 MiB |
| `YOUTUBE_API_KEY` | YouTube Data API v3 키 (선택 — 추천 영상 기능) |
| `YOUTUBE_WHITELIST_CHANNEL_IDS` | 우선 표시할 채널 ID들 (선택, 쉼표 구분) |

전체 Railway 구성과 CORS·마이그레이션 순서는
[`docs/deployment/railway.md`](docs/deployment/railway.md)를 참고하세요.

## 등급/단계 체계

| 등급 | 코치 | 톤 |
|---|---|---|
| 골린이 (beginner) | 김다정 | 비유 중심, 한 번에 한 가지만 |
| 아마추어 (amateur) | 이도현 | 라운드에서 바로 쓸 체크포인트 |
| 세미프로 (semipro) | 정유진 | 클럽 패스/페이스 등 디테일 |
| 프로 (pro) | 한지호 | 정밀도·멘탈·코스 매니지먼트 |

각 등급은 LV-1 → LV-2 → LV-3로 세분화되며, LV-3을 넘어서면 상위 등급 LV-1로
판정될 수 있습니다.

## 개인정보 / 데이터 처리

- 원본 영상은 웹 서버 메모리를 거치지 않고 사용자별 비공개 Bucket 경로에 저장됩니다.
- 영상·분석·작업은 서명된 사용자 ID로 소유권을 확인하며, 닉네임만으로 조회할 수 없습니다.
- Worker가 분석을 위해 만든 임시 파일은 작업 종료 즉시 삭제됩니다.
- Gemini File API에 업로드된 파일도 분석 직후 `deleteFile`로 정리합니다.
- PostgreSQL에는 영상 메타데이터와 **분석 요약(한 줄 코멘트 + 등급/단계 + 코치 메시지 JSON)** 을
  사용자별로 보관해 과거 변화와 숙제 이행을 추적합니다.
