# GOLF-LESSON-APP 상용 런칭 개선 계획

작성일: 2026-07-17
기준 스냅샷: `/Users/judefive/Projects/project/GOLF-LESSON-DEPLOY`
기준 브랜치/커밋: `codex/deployment-foundation` / `9235acdaa9296afa45b7e5be24a514ac325076ad`

## 1. 새 폴더에서 작업하는 이유

- 현재 정상 동작하는 분석 흐름을 보존하고 상용화 변경으로 인한 회귀를 격리한다.
- FFmpeg 교체, YouTube 정책 대응, 인증·약관 작업을 한 번에 섞지 않고 단계별로 검증한다.
- 기존 로컬 폴더로 즉시 돌아갈 수 있는 안전한 비교 기준을 유지한다.
- 런타임 데이터와 Git 메타데이터를 분리해 잘못된 DB 연결이나 브랜치 오염을 방지한다.

## 2. 복사 원칙

- 소스, 설정, 마이그레이션, 문서, 공개 자산과 로컬 `.env`를 복사한다.
- `.git`, `node_modules`, `.next`, `data`는 복사하지 않는다.
- 의존성과 빌드 산출물은 새 폴더에서 `npm ci`, `npm run build`로 재생성한다.
- 로컬 DB는 복제하지 않고 새 개발 DB 또는 별도 스키마를 사용한다.
- `.env`는 로컬 실행을 위한 복사본이며 Git에 커밋하지 않는다.

## 3. 개선 원칙

1. 동작 보존과 법적 정리를 먼저 하고 성능 최적화는 별도 변경으로 진행한다.
2. 한 단계마다 자동 테스트, 실제 영상 회귀 테스트, 성능 기준을 통과해야 다음 단계로 넘어간다.
3. 외부 기능은 기능 플래그로 분리하며 실패해도 핵심 스윙 분석은 계속되어야 한다.
4. 라이선스 검사와 SBOM 생성은 빌드 시 수행하고 사용자 요청 경로에서는 수행하지 않는다.
5. 공개 배포 이미지에는 검증되지 않은 FFmpeg 바이너리를 포함하지 않는다.

## 4. 순차 작업 계획

### 단계 0 — 기준선 고정과 재현성 확보

- 새 폴더에서 `npm ci`, lint, 전체 테스트, production build를 실행한다.
- Safari에서 단일 정면/측면 영상과 멀티샷의 현재 동작을 기록한다.
- 4초 샘플, H.264/HEVC, 30/60fps 테스트 영상을 고정 회귀 세트로 등록한다.
- 분석 전체 시간, FFmpeg 구간별 시간, Gemini 대기 시간, 포즈 검출률을 계측한다.
- Next.js standalone 파일 추적 범위를 바로잡아 `.env`, 소스, 개발 문서가 산출물에 포함되지 않게 한다.
- production DB 모듈과 로컬 PGlite 모듈을 분리하고, 런타임 라우트가 마이그레이션 파일을 동적으로 탐색하지 않게 한다.
- CI에서 standalone 산출물에 `.env`, `data`, 불필요한 프로젝트 루트 파일이 있으면 배포를 실패시킨다.

완료 조건: 원본 폴더와 분석 결과·등급·프레임 타임스탬프가 동일하고 빌드가 성공한다.

### 단계 1 — 런타임 영향이 없는 법적 기반

- 자체 코드의 상용 저작권 고지와 `THIRD_PARTY_NOTICES`를 추가한다.
- 개인정보처리방침, 이용약관, 영상 업로드 권리 보증, AI 가상 코치 고지를 추가한다.
- Gemini, MediaPipe, YouTube 및 저장·삭제 정책을 문서화한다.
- SBOM과 라이선스 검사 작업을 CI에 추가한다.

완료 조건: 법적 문서가 항상 접근 가능하고 런타임 분석 성능 변화가 없다.

### 단계 2 — YouTube 추천을 핵심 분석에서 분리

- 분석 결과를 먼저 저장·완료하고 추천 영상은 별도 비동기 요청으로 처리한다.
- YouTube 결과 순서를 임의 재정렬하지 않고 브랜드 표기를 적용한다.
- 추천 데이터는 분석 이력 JSON과 분리하고 최대 30일 TTL로 갱신 또는 삭제한다.
- `YOUTUBE_RECOMMENDATIONS_ENABLED` 기능 플래그와 빈 결과 폴백을 둔다.

완료 조건: YouTube 장애나 지연이 분석 성공률과 완료 시간에 영향을 주지 않는다.

### 단계 3 — FFmpeg 호환 계층 도입

- FFmpeg 경로와 기능 검사를 담당하는 어댑터를 도입한다.
- 필요한 디코더(H.264, HEVC, VP9/AV1 필요 시), JPEG 인코더와 `scale`, `signalstats`, `metadata` 필터를 시작 시 확인한다.
- 검증된 LGPL 전용 빌드를 별도 이미지에서 사용한다.
- 기존 바이너리는 로컬 비교 테스트에만 사용하고 공개 배포 이미지에서는 제거한다.
- 이 단계에서는 명령과 프레임 추출 알고리즘을 바꾸지 않아 라이선스 교체와 최적화를 분리한다.

완료 조건: 기준 영상의 추출 프레임이 1프레임 이내로 일치하고 분석 등급·구간 점수가 회귀하지 않는다.

### 단계 4 — FFmpeg 성능 최적화

- 중복 메타데이터 검사를 제거하고 한 번 읽은 값을 재사용한다.
- 여러 키 프레임을 가능한 한 한 프로세스에서 추출한다.
- Worker별 FFmpeg 동시 실행 수를 제한해 Railway CPU 고갈을 방지한다.
- 원본 영상을 재인코딩하지 않고 필요한 프레임만 추출한다.

완료 조건: 정확도 기준을 유지하면서 p95 분석 시간이 기준선보다 나빠지지 않는다.

### 단계 5 — Gemini 상용 운영 조건 적용

- 활성 결제 프로젝트의 API 키만 production에 연결한다.
- 동일 모델과 프롬프트를 유지해 등급 판정 회귀를 막는다.
- 18세 이상 확인, 안전 설정, 실패 재시도와 비용·쿼터 모니터링을 적용한다.
- 무료·개발·production 키와 저장소를 완전히 분리한다.

완료 조건: 개인정보가 무료 서비스로 전송되지 않고 모델 결과가 기준선과 일치한다.

### 단계 6 — 데이터 생명주기와 계정 기능

- 영상·분석·추천 데이터별 보존 기간과 사용자 삭제 기능을 구현한다.
- 삭제는 인덱스를 사용하는 배치 Worker에서 처리하고 분석 요청 경로와 분리한다.
- 회원·비회원 트라이얼 데이터를 별도 소유권과 만료 정책으로 관리한다.

완료 조건: 사용자 삭제 요청이 정해진 기간 안에 처리되고 분석 지연을 유발하지 않는다.

### 단계 7 — 별도 Railway 스테이징과 점진 배포

- 기존 서비스와 분리된 Railway 프로젝트·DB·Bucket·Redis를 사용한다.
- 스테이징에서 Safari/Chrome, 단일샷/멀티샷, H.264/HEVC 테스트를 수행한다.
- 오류율, p50/p95 처리시간, 포즈 검출률, Gemini 비용을 모니터링한다.
- 소수 테스트 사용자부터 점진적으로 공개하고 롤백 이미지를 유지한다.

완료 조건: 핵심 지표가 기준을 충족하고 고위험 라이선스·약관 항목이 모두 해소된다.

## 5. 우선순위와 변경 분리

- P0: 기준선·테스트 → standalone 추적/비밀정보 차단 → 법적 문서 → YouTube 분리 → LGPL FFmpeg 교체
- P1: FFmpeg 프로세스 최적화 → Gemini 상용 설정 → 데이터 삭제
- P2: 점진 배포·비용 최적화·상표 최종 검토

FFmpeg 교체와 성능 최적화는 같은 커밋에서 진행하지 않는다. YouTube 수정도 별도 커밋으로 유지해 문제가 생기면 기능 단위로 되돌릴 수 있게 한다.
